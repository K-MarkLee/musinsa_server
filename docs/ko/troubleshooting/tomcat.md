# 상품 상세: Tomcat 스레드 수와 연결 대기

[English](../../en/troubleshooting/tomcat.md) · [README](../../../README.ko.md)

---

## 문제와 비교 조건

Hikari 50으로 연결 대기를 줄인 뒤에도 3,000 RPS에서 처리량이 약 2,100 RPS에 머물렀고, Tomcat busy 스레드는 상한 200에 막혔습니다.<br>
스레드를 늘리면 처리량이 늘어나는지 보기 위해 Hikari를 50으로 고정하고 Tomcat 50, 200, 500을 비교했습니다.

상품 5개를 번갈아 조회했고, VU 상한 1,000, timeout 5초로 설정마다 1회씩 실행했습니다.<br>
부하는 Hikari 실험 2와 같은 단계(50 → 1,000 → 1,500 → 2,000 → 3,000 → 50 RPS)입니다.

---

## Tomcat 50, 200, 500: 스레드 수와 연결 대기

| Hikari 50 고정 | Tomcat 50 | 200 | 500 |
| --- | ---: | ---: | ---: |
| 2,000 RPS 처리량 (RPS) | 1,999 | 1,998 | 1,998 |
| 2,000 RPS 평균 (ms) | 51.2 | 77.2 | 73.3 |
| 2,000 RPS p95 (ms) | 158.4 | 265.9 | 238.2 |
| 2,000 RPS p99 (ms) | 253.9 | 434.6 | 446.3 |
| 3,000 RPS 처리량 (RPS) | 2,112 | 2,121 | 2,063 |
| 3,000 RPS 평균 (ms) | 472.0 | 469.4 | 482.9 |
| 3,000 RPS p95 (ms) | 613.3 | 632.6 | 901.6 |
| 3,000 RPS p99 (ms) | 724.3 | 758.3 | 1,312.9 |
| 3,000 RPS 평균 연결 사용 | 49.6 | 49.8 | 49.9 |
| 3,000 RPS 평균 연결 대기 | 0 | 149.8 | 449.9 |
| 3,000 RPS 평균 Tomcat busy | 50 | 200 | 500 |
| 3,000 RPS 호스트 CPU 평균 | 96.6% | 96.6% | 96.8% |
| 전체 drop | 57,148 | 57,291 | 61,498 |

Tomcat을 200에서 500으로 늘리자 연결 대기가 약 150건에서 450건으로 늘었지만, 실제로 DB 연결을 쓰는 작업은 약 50개로 같았고 처리량도 늘지 않았습니다.<br>
오히려 3,000 RPS의 p95가 632.6ms에서 901.6ms로 길어졌습니다.<br>
반대로 Tomcat 50은 연결 대기가 0이었지만 처리량은 역시 약 2,100 RPS였고, 2,000 RPS에서는 p95가 세 설정 중 가장 낮았습니다.

스레드를 늘리면 연결 풀 앞의 대기가 늘고, 스레드를 줄이면 그 대기가 요청 큐로 옮겨갈 뿐 처리량은 달라지지 않았습니다.

---

## 판단

Tomcat은 200으로 유지했습니다.<br>
3,000 RPS에서는 스레드 수와 상관없이 호스트 CPU가 96%를 넘어 처리량이 약 2,100 RPS에서 멈췄고, 스레드를 늘리면 대기와 지연만 늘었습니다.<br>
Tomcat 50은 상세 API 하나만 놓고 보면 지연이 가장 낮았지만, 다른 API와 함께 쓸 때도 그런지는 확인하지 않아 200을 유지했습니다.

대기를 연결 풀에 둘지 요청 큐에 둘지는 설정으로 바꿀 수 있어도, 처리할 수 있는 양은 이 장비의 CPU가 정한다는 것을 확인했습니다.
