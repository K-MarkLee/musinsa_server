# 상품 상세: Tomcat 스레드 수와 연결 대기

[English](../../en/troubleshooting/tomcat.md) · [README](../../../README.ko.md) · [공통 측정 환경](../environment.md)

Hikari 50으로 연결 대기를 줄인 뒤에도 3,000 RPS 목표에서 처리량이 약 2,100 RPS에 머물렀다.<br>
Tomcat busy가 상한에 도달해 작업 스레드를 늘리면 처리량이 증가하는지 비교했다.

---

## 시나리오와 비교 기준

상품 5개를 순환하고 Hikari 50, k6 사전 할당·상한 1,000 VU, HTTP timeout 5초를 고정했다.<br>
Tomcat 50·200·500을 각각 1회 측정했다.<br>
부하는 50 RPS 30초 → 1,000 RPS 45초 → 1,500 RPS 60초 → 2,000 RPS 75초 → 3,000 RPS 60초 → 50 RPS 30초이며, 각 단계 사이 15초 전환을 포함해 총 6분 15초다.<br>
성능 기준에 따른 자동 중단은 해제했다.

Tomcat 200은 같은 확장 시나리오의 Hikari 50 실행을 사용했다.<br>
초기 5분 실행과 섞지 않는다.<br>
처리량은 유지 단계 완료 건수÷유지 시간의 근삿값이며 메트릭 평균은 해당 유지 구간의 1초 간격 조회다.<br>
전체 drop은 3,000 RPS 구간만의 합계가 아니다.

---

## Tomcat 50·200·500: 연결을 기다리는 스레드만 증가

| Hikari 50 고정 | Tomcat 50 | 200 | 500 |
| --- | ---: | ---: | ---: |
| 2,000 RPS 처리량 약 | 1,999 | 1,998 | 1,998 |
| 2,000 RPS 평균, ms | 51.2 | 77.2 | 73.3 |
| 2,000 RPS p95, ms | 158.4 | 265.9 | 238.2 |
| 2,000 RPS p99, ms | 253.9 | 434.6 | 446.3 |
| 3,000 RPS 처리량 약 | 2,112 | 2,121 | 2,063 |
| 3,000 RPS 평균, ms | 472.0 | 469.4 | 482.9 |
| 3,000 RPS p95, ms | 613.3 | 632.6 | 901.6 |
| 3,000 RPS p99, ms | 724.3 | 758.3 | 1,312.9 |
| 평균 Hikari active | 49.6 | 49.8 | 49.9 |
| 평균 Hikari pending | 0 | 149.8 | 449.9 |
| 평균 Tomcat busy | 50 | 200 | 500 |
| 호스트 CPU 평균 | 96.6% | 96.6% | 96.8% |
| 전체 drop | 57,148 | 57,291 | 61,498 |

표의 네 평균 메트릭은 3,000 RPS 유지 구간 값이다.<br>
200→500에서 pending은 약 150→450으로 늘었지만 실제 DB 연결 작업은 약 50개로 같았고 처리량은 늘지 않았다.<br>
p95는 632.6→901.6ms로 증가했다.

Tomcat 50은 Hikari pending이 0이어도 처리량이 약 2,112 RPS에 머물렀다.<br>
세 실행 모두 HTTP 오류·연결 timeout은 0이었지만 drop이 남았다.<br>
Hikari 대기 수만 줄이는 것으로 목표 요청량을 처리할 수는 없었다.

---

## 판단과 선택

Tomcat 200→500 증설은 처리량을 높이지 못했고 연결 대기와 p95를 늘렸다.<br>
증설을 되돌리고 로컬 기준은 200으로 유지했다.<br>
50에서는 이번 상세 시나리오의 p95가 가장 낮았으므로, 더 작은 스레드 풀은 혼합 API 부하에서 비교할 후보로 남겼다.

2,000 RPS에서는 세 설정 모두 약 1,999 RPS를 처리했지만 평균·p95·p99가 달랐다.<br>
3,000 RPS에서는 스레드를 늘려도 연결 작업 약 50개의 처리 능력은 늘지 않았고 대기가 늘었다.<br>
스레드 제한으로 Hikari pending을 낮추는 것과 요청 전체 대기를 없애는 것은 다르므로, 하나의 큐 수치가 아닌 처리량·지연·drop을 함께 판단했다.
